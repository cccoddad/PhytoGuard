# 总休整方案（秋招版）

目标：把 PhytoGuard 从「能看」变成「能跑、能讲、能扛追问」，作为简历第三项目与面试弹药。

## 一、方向定位

| 方向 | 匹配度 | 说明 |
|------|--------|------|
| 嵌入式软件工程师（Linux 系统/平台） | 主打 | 海思媒体管线、I2C 驱动、交叉编译、开机自启、ACL 模型生命周期、守护进程自愈 |
| 边缘 AI / 端侧推理部署 | 次打 | 海思 ATC/ACL 工具链国内会的人少；两阶段级联 + 模型懒加载是有深度的设计决策 |
| AIoT / 物联网全栈 | 备选 | 4G 模组 AT 指令 + 云端 API + 小程序端到端 |
| 音视频 / 流媒体 | 不用 | 本项目无编解码推流，音视频故事在 RK3568 项目 |
| 算法岗 | 撑不起 | 只有训练脚本，无模型创新 |

## 二、两项目话术分工（避免重复）

- **RK3568 音视频边缘网关**：端侧 AI + 音视频实时性 + 并发架构（6 线程有界队列、120h 长稳）
- **PhytoGuard**：国产海思平台系统级开发 + 传感器总线驱动 + 端云协同
- 合起来的辨识度：同时拿下 RK 与海思两条国产 SoC 生态

- [x] **阶段一 止血**：cloud 目录归位 / 密钥脱敏 / 4 个 shell 脚本重写 / README 对齐（2026-09-28 完成）
- [ ] **阶段二 可验证**：git 恢复 / 一键启动 / 无硬件回放演示模式（git 已于 2026-09-28 全新初始化，历史不可恢复）

- [ ] **阶段四 简历与题库**：三项目编排 + PhytoGuard 面试题 60~80 问

## 四、排期与优先级

```
第 1 天   阶段一          → 项目从"能被挑刺"变成"能被打开"
第 2-3 天 阶段二 + 简历文案 → 可以先挂简历投递
第 4-8 天 阶段三 + 题库    → 面试前的弹药
```

**优先级：阶段三 > 阶段一。**
面试官不会 `cat` 你的 init 脚本，但一定会问「8ms 怎么测的」「为什么不用一个 16 类模型」。
时间不够时，先做 cloud 归位与脱敏（跑不起来、密钥泄露是硬伤），脚本重写可以放最后。
